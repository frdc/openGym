# Temporary Firebase Node transport override

The frontend pins official `firebase` to **12.19.0** for the Node 22 toolchain. Its Firestore 4.17.2 package requests `@grpc/grpc-js ~1.9.0`, which resolves an affected release. `frontend/package.json` therefore overrides **only** `@firebase/firestore@4.17.2`'s gRPC dependency to exact **1.13.6**. This is a reviewed exception outside Firebase's declared range, not a fix supplied by Firebase.

The gRPC maintainer identifies 1.13.6 and 1.14.5 as patches for [GHSA-m9gg-hp2v-232j](https://github.com/grpc/grpc-node/security/advisories/GHSA-m9gg-hp2v-232j) (unauthorized client certificate context) and [GHSA-f596-whhp-79r4](https://github.com/grpc/grpc-node/security/advisories/GHSA-f596-whhp-79r4) (server handler error detail disclosure). Versions 1.14.0–1.14.4 are also affected; do not replace the exact pin with a broad `>=1.13.6` rule. The patched release retains the public client APIs used by Firestore. Its existing proto-loader 0.7.15 resolution remains, and it adds ordered-map as a transitive dependency.

Firebase 13.0.0 still requests the affected gRPC range and its App/Auth/Firestore packages require Node >=24.12.0, so that upgrade does not solve this issue on this toolchain. Compare the official [Firestore 4.17.2 manifest](https://registry.npmjs.org/@firebase%2ffirestore/4.17.2), [Firestore 4.18.0 manifest](https://registry.npmjs.org/@firebase%2ffirestore/4.18.0), and [gRPC 1.13.6 release](https://github.com/grpc/grpc-node/releases/tag/%40grpc%2Fgrpc-js%401.13.6).

gRPC belongs to Firestore's **Node** transport. The isolated Firebase client/Auth Vite bundle probes select browser Firestore and exclude gRPC, compat, Storage, and Analytics. Repeat module inventory on the fully integrated web/mobile application; probe bundles alone do not prove the final application or signed Android artifact's contents. The distributed Firestore Node adapter's telemetry may still say `grpcVersion=1.9.16`; verify actual resolution with `npm ls` and package metadata, without editing vendor files.

Real Node transport compatibility must be verified against loopback-only `demo-opengym` emulators during Firestore adapter integration: authenticated server read/write, query, transaction, listener, permission errors, disconnect/reconnect, and cleanup. Auth/config unit tests and SDK initialization do not establish those transport behaviors.

When upgrading Firestore, **remove or reassess this override**. Its exact parent selector deliberately stops matching newer Firestore versions. Require clean full/production audits, inspect the resolved gRPC/proto-loader tree, preserve unrelated lockfile resolutions, and repeat Node emulator and browser bundle verification. Do not use a global override or `npm audit fix --force`.
